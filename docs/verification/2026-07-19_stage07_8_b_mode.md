# Stage 07.8 B-channel tracking and phase mode gate

## Implemented behavior

- `COMMON_PPM`: for a non-integer A/B frequency ratio, B receives the same relative FTW
  correction as A.
- `DERIVED_INTEGER`: FPGA generates `phase_B = N * phase_A + phase_offset` modulo 2^32.
- Derived phase accepts 0 through 180 degrees in 5-degree increments.
- B mode may only be changed while the DPLL is stopped.
- Positive phase means B leads the `N * A` digital phase by the configured offset.

Commands:

```text
CMD:DPLL_B_COMMON
CMD:DPLL_B_DERIVED,<ratio_n>,<phase_deg>
```

## Offline gate

```powershell
python tools/automation/test_dpll_b_mode.py
```

Result:

```text
DPLL_B_MODE_PASS phase_0_180_step_5=1 common_ppm=1 derived_ratio=1
```

The production C implementation was compiled with `-Wall -Wextra -Werror`. Coverage includes
0/90/180-degree exact mappings, invalid phase values, positive and negative common-ppm
corrections, valid integer ratios and frequency/ratio mismatches.

## Board digital gate

```powershell
python tools/automation/test_stage07_8_b_mode.py --port COM16
```

Result: `PASS`.

- All 37 phase commands from 0 to 180 degrees in 5-degree steps were accepted.
- A 3-degree phase and a frequency-inconsistent ratio were rejected.
- At A=30 kHz, B=60 kHz, N=2 and 90 degrees, the active FTWs satisfied
  `FTW_B = 2 * FTW_A`.
- The atomic snapshot satisfied
  `phase_B - 2 * phase_A = 0x40000000` exactly.
- At A=30 kHz and B=50 kHz, common-ppm mode produced the expected B FTW within one LSB.
- Snapshot, phase, sequence and commit failure counters remained zero.
- The FPGA protocol CRC counter remained stable at `110 -> 110`.
- Firmware build and OpenOCD flash passed.

Regression gates after the change:

- Stage 07.7 closed-loop/fault-recovery test: `PASS`; locked RMS `0.0939 deg`, peak
  `0.2297 deg` in the numerical bridge data.
- Stage 07.4 1000-snapshot protocol test: `PASS`; LL timeout/error counts remained zero.

## Evidence boundary

This proves the digital FTW and phase relationships in the implemented FPGA snapshot domain. It
does not prove the analog phase at the DA connectors. Cable delay, DAC channel skew, reconstruction
filter delay and probe skew remain outside the digital identity and require an oscilloscope sweep.
The 0-to-180-degree, <=5-degree-error requirement remains `BENCH_PENDING` until measured values
are recorded.

## User oscilloscope observation

The user applied the following derived-B configuration on the programmed board:

```text
CMD:DPLL_CONFIG,30000,60000,100
CMD:DPLL_B_DERIVED,2,90
CMD:DPLL_CLOSED_LOOP_START
```

The observed A-prime/B-prime relationship at 90 degrees matched expectation. The user also tested
180 degrees and reported the expected relationship. These observations confirm connector-level
behavior for the tested settings, but remain qualitative: no measured phase values, screenshots,
probe/cable configuration or error calculation were recorded, so the formal <=5-degree
`BENCH_PASS` remains pending.
